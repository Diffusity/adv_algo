Same optimal path, different exploration cost

Every algorithm returns a path of the same optimal cost. The difference is how many cells it had to reveal. MXA* and MXA*-ID reveal the same cells in a single query; MXA*-ID is faster because it repairs the distance oracle incrementally instead of rebuilding it.

What the colours mean

Unknown is not free

A grey cell has never been selected by the search. The algorithm may assume it is passable while planning, but it only learns the truth when it explores the cell. Discovering a wall can invalidate a planned route.

Dynamic heuristic

MXA* maintains the exact distance hD(v) to the goal in the currently known graph. As obstacles are revealed, the proposed incremental oracle repairs only the affected part of the shortest-path tree instead of rebuilding it from scratch.

Memory across queries

The multi-query experiment reuses discovered obstacles. In the report, this cuts cumulative explorations by 20–55% over ten queries. The demo shows one query at a time so the trace stays readable.

No hidden suboptimality

The heuristic is admissible and consistent. Every run in the benchmark matrix is checked against an omniscient Dijkstra reference; the largest relative cost gap was 5×10-16, i.e. floating-point noise.
